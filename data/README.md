# data/

Real site map for SiteSense: Cittadella Universitaria, Catania (OSM way 231201634).

| File | What |
|---|---|
| `site.json` | Site definition (hand-written); `mapFile` points to the map. Body of `POST /api/v1/sites`. |
| `map.geojson` | Site map in the SiteSense map format, generated by `build_map.py`. Body of `PUT /api/v1/sites/{siteId}/map`. |
| `osm/cittadella.osm.gz` | Saved OpenStreetMap extract: the input of the script. |
| `build_map.py` | Downloads the extract, converts it to `map.geojson` and checks the map rules. |

## Run it

Needs Python 3.9 or later. Standard library only: nothing to install.

```bash
python3 data/build_map.py             # convert the saved extract (offline)
python3 data/build_map.py --download  # fetch a fresh extract from the OSM API, then convert
python3 data/build_map.py --help      # list the options
```

- Without `--download` the output is byte-identical on every run. Check it with `git status data/`: nothing changes.
- With `--download` the map follows today's OSM data, so it can differ from the committed one.
- On a failed map rule the script prints `RULE CHECK FAILED <element> <reason>`, exits with code 1 and leaves `map.geojson` as it was.
- On success it prints `rule check passed` and a summary: counts per kind and area type, what it dropped and why.

## Options

| Option | Default | What |
|---|---|---|
| `--download` | off | Fetch the extract from the OSM API before converting. |
| `--way` | `231201634` | OSM **way** id of the site perimeter (a closed way). |
| `--bbox` | `15.0670,37.5230,15.0790,37.5332` | Area to download: `west,south,east,north` in degrees. Must cover the whole perimeter. |
| `--name` | `Cittadella Universitaria` | Name of the perimeter area in the map. |
| `--osm` | `data/osm/cittadella.osm.gz` | Extract file to write (with `--download`) and read. |
| `--out` | `data/map.geojson` | Map file to write. |

## Build another site

1. **Find the perimeter way id.**
   1. Open <https://www.openstreetmap.org>, search the site and zoom in.
   2. Click the query tool (the `?` arrow on the right), then click inside the site.
   3. Under "Enclosing features", pick the site outline, e.g. "University …" or "Industrial area …".
   4. The page shows `Way: <name> (<id>)`. That number is `--way`.
   - It must be a **way**. A **relation** (a multipolygon) is not supported: pick another site or another outline.
2. **Get the bbox.**
   1. On the way's page, click "Export" in the top bar.
   2. The box shows the four limits of the current view: left = west, bottom = south, right = east, top = north.
   3. Zoom so the whole site fits with a small margin, and copy the four numbers as `west,south,east,north`.
   - Keep it small. The OSM API refuses an area over 0.25 square degrees or with more than 50 000 nodes (HTTP 400); a campus or industrial site of 1–2 km is far below that.
3. **Check that the site has assembly points.** The script uses the real `emergency=assembly_point` nodes from OSM and never invents them. With none inside the perimeter it stops with `RULE CHECK FAILED assemblyPoint: no assembly point`. To check before you run: open <https://overpass-turbo.eu>, move the map to the site and run `node["emergency"="assembly_point"]({{bbox}}); out;`.
4. **Run it.** Use a new extract file, so the Catania extract is kept:

   ```bash
   python3 data/build_map.py --download --way <id> --bbox <w,s,e,n> --name "<site name>" --osm data/osm/<site>.osm.gz --out data/<site>.geojson
   ```

   Later runs on the same site need the same options, without `--download`.
5. **Write the site JSON.** Copy `site.json` and change `siteId`, `name`, `timeZone` (IANA name, e.g. `Europe/Rome`) and `mapFile`. Keep `navigation`, or tune it: speeds in m/s, factors as multipliers, distances in metres.
6. **Record the source.** Add the site to [DATA_SOURCES.md](../DATA_SOURCES.md): way id, API URL with the bbox, download time (the script prints it), ODbL licence.

## What the script does

1. Reads the extract and rounds every coordinate to 7 decimals.
2. Turns the perimeter way into the `perimeter` area. Other closed ways fully inside it become areas, in priority order: `hazard` (construction, water), `restricted` (`power=*`), `work` (buildings), `parking`, `rest` (gardens, pitches, grass). An area that overlaps one already taken is dropped.
3. Turns `highway=footway/path/pedestrian/steps/service/track/living_street` into paths, cut where they leave the perimeter. Paths that cross or touch get a shared vertex, except across different layers, bridges or tunnels.
4. Makes an entrance at each path node that lies on the perimeter.
5. Snaps each assembly point onto the nearest walkable path segment (one outside `restricted` and `hazard` areas), at most 30 m away.
6. Keeps the largest connected walkable network and drops paths cut off from it.
7. Checks every map rule, then writes the map.

Full mapping table and the reasons behind each rule: [docs/plans/SS-18-osm-map.md](../docs/plans/SS-18-osm-map.md).

### Path properties

| Property | From OSM | Default |
|---|---|---|
| `surface` | `surface=*`: asphalt, paving stones, concrete… → `paved`; gravel, dirt, grass… → `unpaved` | `unpaved` for `track` and `path`, `paved` for the rest |
| `steps` | `highway=steps` | `false` |
| `slopePercent` | `incline=*` when it is a number in % | `0` |
| `widthM` | `width=*` when it is a number in metres | by type: footway 2, path 1.5, steps 2, pedestrian 4, track 3, service 4, living street 5 |

To change a mapping, edit the constants at the top of `build_map.py` (`AREA_PRIORITY`, `PATH_HIGHWAYS`, `DEFAULT_WIDTH`, `PAVED`, `UNPAVED`).

## Known limits

- `slopePercent` is 0 for almost all paths: OSM has no elevation, and only a numeric `incline=…%` is used.
- Crossings between paths on different layers, bridges or tunnels are not joined by a shared vertex.
- Areas outside the perimeter, overlapping areas and multipolygon relations are dropped. The script prints the counts.
